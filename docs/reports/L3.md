# L3: tools.doji.motionbricks / MotionBricks in Unity Inference Engine

## 1 Verdict: YELLOW (leaning GREEN for the network, RED for "package does it all")
The community package source is **not public**, so we cannot use it as a drop-in. But the published `.sentis` model loads and runs on Unity 7000.0.0a12 + Inference Engine 2.6.1 with GPUCompute, and matches the official TensorRT output to numerical noise. The remaining work is porting the engine logic (about 1,000 Python/Warp lines) to C#. Speed is the catch: about 30 ms per generation (6x slower than TensorRT) with a 20 s first-call stall.

## 4 Conflicts
- L9 "docs/OpenUPM 404" confirmed, and extends to GitHub: the package is not in any public source I could find. The HF page nevertheless presents it as installable; likely private or paid.
- HF README says Inference Engine "2.6.1" saved with Unity "6000.6.4f1" (sentis.json); fine on 7000.0.0a12 anyway.
- ONNX 758 MB vs .sentis 757 MB: both checksums match `SHA256SUMS`.

## 5 Unknowns
Package source, version, license, whether it includes the SOMA engine logic; ONNX import path in 7000.0.0a12; interactive-Editor stall behaviour; async/ScheduleIterable cost; FP16 weight option speed (HF says same GPU speed); batch>1 speed; whether Vulkan is the default Editor API on this machine (the user's Editor used for TestingAssets was not inspected).

## 6 Risks
- Community package may stay closed; depends on a third party's model-hub. Mitigation: use the HF files directly (NVIDIA Open Model Agreement terms apply; check redistribution before bundling).
- 30 ms/gen is 6x slower than TRT; acceptable for in-betweening at about 30 Hz, tight for many characters. Graphics API matters 4x (GL 135 ms vs Vulkan 30 ms).
- 757 MB model, about 810 MB VRAM, 20 s warmup.
- Alpha Editor (7000.0.0a12) is unsupported by the package (Unity 6000.0 minimum); it worked here only in batchmode.
- Port must reproduce the heading alignment and 6D encodings exactly; parity harness above provides ground-truth tensors (`work/ref/*.npz`).

## Option 5 recommendation
Take the ONNX/sentis in Inference Engine plus our own C# port (about 1,000 lines). motion-bricks.cpp is G1-only (README), so it does not help for SOMA.
