# L9: Prior integrations of MotionBricks / SOMA with engines and 3D tools (dated 2026-11-07)

## 1 Verdict: YELLOW
Two real third-party integrations exist (Unity via Inference Engine; s&box editor tool). A third, motion-bricks.cpp, targets Go/Three.js. Each has caveats:
- The Unity package could not be opened (UNVERIFIED), though its model repo exists and is VERIFIED.
- The s&box tool uses the G1 skeleton, not SOMA.
- motion-bricks.cpp supports G1 only.
- NVIDIA's Unreal plugin has no release date.
- I found no Blender or Godot integration, and no published SOMA-to-Mixamo or SOMA-to-Unity-Humanoid bone map.
- Nobody has shipped an end-to-end SOMA in a game engine that I could confirm.
- Ready-made BVH-to-Unity-Humanoid tools exist, but all are fragile on rest pose.

## 3 Unknowns
- Whether tools.doji.motionbricks exists publicly: its version, license, whether it runs SOMA (the HF repo ships SOMA weights, so INFERRED yes), and whether it includes retargeting to a humanoid Avatar. Source repo not found, docs 404.
- The s&box tool's license and update date, and whether it supports SOMA (it uses G1 in the code described).
- Whether the ARDY repo and weights are public, and their license.
- SOMA's full 77-joint names. Nobody has published a SOMA to Mixamo or Unity Humanoid map that I found (VERIFIED absent from the pages I opened; search coverage was one query plus SOMA-X's README). It would have to be built by hand from the SOMA-X skeleton definition.
- Whether the SOMA-X docs/tools.md covers BVH or FBX export.
- Reddit, YouTube and forum coverage: only a few web searches, which returned nothing on MotionBricks plus Godot, Blender or Three.js beyond the C++ port's Three.js demo.

## 4 Risks
- Licensing (VERIFIED): the models are under the NVIDIA Open Model Agreement, and the sample motions under a separate evaluation license. The code is Apache-2.0. Redistributing converted weights (.sentis, GGUF) carries NVIDIA's terms. Read the agreement before shipping.
- Unity route is heavy: FP32 weights of 757 MB; no quantisation (VERIFIED). Latency in-engine is unmeasured (INFERRED). On PR #3's M3 Max numbers, the Python runtime takes ~110-177 ms per generation on non-NVIDIA hardware (VERIFIED, author's measurement).
- Official runtime needs TensorRT/NVIDIA GPU; the non-NVIDIA PRs are unreviewed and may never merge (VERIFIED: no maintainer comments).
- NVIDIA repo is thin (2 commits, no releases) and the Unreal plugin has no date. API and model files may change (INFERRED).
- A commenter on issue #170 reported that the released model seemed to include far fewer animations than shown in demos (opinion, VERIFIED as reported).
- A single maintainer of each community port (INFERRED) means bus-factor risk; download count of 26/month signals little adoption.
- Kimodo and ARDY outputs have no BVH or FBX export in the docs I read, so a converter from NPZ rotation matrices would likely be needed (INFERRED).
- SOMA pose to Unity Humanoid retargeting is uncharted; rest-pose mismatch is the main expected problem (INFERRED).
