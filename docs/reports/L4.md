# L4: SOMA (MotionBricks) to SA clip, feasibility

Branches read (local refs, no fetch): com.sa.unity `packet/RESIDUAL-gates` @930377d (RES), sa-motion `packet/RAGDOLL-pilot` @8452244 (RP), motionbricks @54fc563 (MB).

## 1 Verdict: YELLOW

Route D (direct) is feasible with almost no new runtime code. Every encode and retarget primitive exists, and the SACA format already has a 4-channel contact chunk. YELLOW because of three gaps: (a) the SOMA rest pose is not a T-pose (MB BVH frame 0 has Hips about Z89/X94), so a calibration step has to be written; (b) no Unity system feeds authored contacts to leg IK; (c) MB has no SOMA exporter, so a small dump script is needed.

## 2 Answers

1. **Today there are two extractors, both Editor-side, and both use `AnimationClip.SampleAnimation`, so Humanoid and Generic clips both work. VERIFIED.**
   - Per-rig SA clip: `RigBuilder.BuildClip` (RES `Editor/RigBuilder.cs:264`). It outputs a `Clip` blob (`Runtime/Data/Rig.cs:12-21`) with no contact field. Per `docs/workflow.md:33,41` it is "any Humanoid clip on any Humanoid character", through Unity retargeting.
   - Canonical humanoid-v1 clip: `SharedFamilyBaker.BakeClip` (RES `Editor/SharedFamilyBaker.cs:839`), with sampling in `SampleRigClip` (:952). It maps bones by name with `SolveMap` (:768) using `ScoreBoneName` (:172) and `MappingAssignment.Solve`, then encodes with `EncodeCanonicalSamples` (:339), which calls `SharedClipEncoder.Encode` (:359).
   - `CanonicalBakeExtract` (RES `Editor/CanonicalBakeExtract.cs:50`, menu "Extract Canonical Samples") writes JSON under `Temp/sa/c08` for conformance. It requires a valid Humanoid Avatar (:79-90).
2. **Route M losses (INFERRED, from standard Mecanim behaviour):**
   - Twist is redistributed and roll is clamped by muscle limits.
   - Feet and hands drift unless IK goal curves are written, and `HumanPoseHandler` gives only muscles plus body pose.
   - SOMA Neck1/Neck2 collapse into a single Neck.
   - The motion is retargeted twice (SOMA to muscle to target rig, then to canonical).
   - Root travel is dropped by the family bake (VERIFIED warning at `SharedFamilyBaker.cs:856`).
   - It needs a Humanoid Avatar for SOMA, built with `AvatarBuilder.BuildHumanAvatar` and a hand-written HumanDescription.
3. **Route D reusable APIs (VERIFIED, RP unless noted):**

| Need | API | file:line |
|---|---|---|
| Canonical 56-bone ref (T-pose, Y-up, +Z fwd, Hc=1 m) | `CanonicalHumanoid.WriteReference` | `src/SA.Animation/Retarget/CanonicalHumanoid.cs:11` |
| Rest-frame correction | `RetargetTable.Compile` (rotation-only: `inv(srcModel)*tgtModel`; assumes the same anatomic pose) | `src/SA.Animation/Retarget/RetargetTable.cs:51-114` |
| Build T-pose calibration | `CalibrationFrame.TryRotation` | `src/SA.Animation.Content/MappingAssignment.cs:93-95` |
| Bone mapping | `MappingAssignment.Solve`; RES `SharedFamilyBake.ScoreBoneName` | `MappingAssignment.cs:18`; RES `SharedFamilyBaker.cs:172` |
| Encode SACA | `SharedClipEncoder.Encode(..., contactWeights, ...)` | `src/SA.Animation.Content/SharedClipEncoder.cs:34`, contacts :43, :151-155 |
| Verify | `SharedClipReader.Load` → `SharedClip.ContactWeights` | `SharedClip.cs:56`, `:34` |
| Canonical to target to ECS blob | the per-frame loop in `BakeClip`, plus `SharedFamilyBake.MakeClipBlob` | RES `SharedFamilyBaker.cs:862-917`, `:98` |

   The name scorer should not be used for SOMA. "LeftLeg" is the thigh and "LeftArm" is the upper arm, and both tokenize to the ambiguous "leg"/"arm" (Alias at :256). "*ThumbEnd" also risks matching Thumb. Use a fixed 30→56 table instead. INFERRED.
4. **Only Route D keeps contacts. VERIFIED for the format, INFERRED for the conclusion.** An `AnimationClip` has no contact channel, and both bakers ignore one.
   - `Encode` takes `sampleCount*4` floats into a `CONT` chunk.
   - The core planter honours authored contact: `Planting.Decide` reads `contactAuthored` first (`src/SA.Motion/Legs/Planting.cs:11-12`), fed from `LegInput.ContactAuthored/Contact` (`LegTypes.cs:34-35`, `LegRig.cs:78`).
   - Gaps: the RES baker passes `Array.Empty<float>()` (`SharedFamilyBaker.cs:360`), and no Unity system sets `ContactAuthored` (grep shows no writer outside `src/`).
   - Layout mismatch: SA CONT is [LFoot, RFoot, LHand, RHand] (`docs/shared-animation-plan.md:747`), while MB is [LHeel, LToe, RHeel, RToe] (`motionbricks/animation/foot_contacts.py:4-8`). A heel/toe merge is needed, for example `max(heel, toe)`, which loses the roll information.
   - This bears directly on issue #1. Authored contact bypasses the PlantRise, ReleaseRise and PinRadius thresholds that are the suspected cause of the chatter. INFERRED.
5. **UniHumanoid:** MIT, archived since 2018-12 (VERIFIED with `gh api`). Its BVH reader and HumanDescription guessing are useful to read for Route M only. **BVH Tools for Unity (emilianavt):** MIT (VERIFIED from LICENSE.txt), last pushed 2022-08, imports BVH onto a Humanoid at runtime. Neither is needed for Route D: MB data is already in-memory arrays, and neither handles contacts. Do not vendor either.
6. **Recommendation: Route D.**
   - It keeps contacts and twist.
   - It is one retarget instead of two.
   - It fits the "no Animator at runtime" rule. Editor-only use is fine either way, but D does not need Mecanim even at bake time.
   - All encoders exist.

   **Smallest spike:**
   1. Python (`-I`, CPU): run MB SOMA on one locomotion clip and dump JSON with the 30 joint parents, reference locals, per-frame local quats plus hip position (m, Y-up), and contacts [N,4] at 30 Hz.
   2. .NET xUnit in sa-motion (no Unity):
      - pose SOMA into the canonical T-pose with `TryRotation`;
      - `RetargetTable.Compile` using the fixed map;
      - convert to 56-bone samples;
      - `SharedClipEncoder.Encode` with merged contacts;
      - `SharedClipReader.Load`.
   3. Pass criteria: round-trip at or under `CompressionLimits.Default` (0.15°, 2 mm); foot sole height under 2.5 cm where contact ≥ 0.5; `ContactWeights` preserved.

   The Unity preview and ECS playback come in a second step, using `MakeClipBlob`.

**Baseline (VERIFIED):** com.sa.unity `packet/RESIDUAL-gates` contains C08 and C12, and also C11's `AnimationLibraryWindow.cs` plus a newer extractor. Pair it with sa-motion `packet/RAGDOLL-pilot`, which contains CF1, L1-legs, C08, C09, C13-C14 and SH1.

## 6 Risks

- Bad T-pose calibration produces systematic limb twist. Mitigate with a world-space bone-direction check against the canonical model.
- Spine1/2/Chest map onto Spine/Chest/UpperChest at different heights.
- Root policy: the family bake drops travel, so root motion has to be written via the `RootPolicy` and `root` arguments of `Encode`.
- Wiring contacts into the Unity `LegIKSystem` (sa-motion `packages/com.sa.unity.reactions`) is unbuilt work.
- MotionBricks licence: the code is Apache-2.0, but the sample motions are under the NVIDIA evaluation licence (`assets/motions/LICENSE.txt`).
